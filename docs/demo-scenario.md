# Сценарий демонстрации DoIt v0.2

Этот сценарий помогает показать MVP проекта последовательно и без пропусков.

## 1. Запуск проекта

1. Открыть терминал в папке проекта.
2. Создать `.env`, если его еще нет:

```bash
cp .env.example .env
```

3. Запустить проект:

```bash
docker-compose up --build
```

4. Открыть приложение:

```text
http://localhost:8000
```

## 2. Подготовка demo-данных

В отдельном терминале выполнить:

```bash
docker-compose exec web python manage.py seed_demo_data
```

После этого доступны:

- пользователь `demo_user`;
- администратор `demo_admin`;
- задачи разных статусов;
- записи журнала действий.

Пароли по умолчанию:

- `demo_user` / `DemoUser12345`;
- `demo_admin` / `DemoAdmin12345`.

## 3. Регистрация и вход

1. Открыть страницу регистрации:

```text
http://localhost:8000/accounts/register/
```

2. Показать поля формы регистрации.
3. Создать нового пользователя или перейти к входу.
4. Открыть страницу входа:

```text
http://localhost:8000/accounts/login/
```

5. Войти под `demo_user`.

## 4. Личный кабинет

Показать:

- имя пользователя;
- роль `user`;
- статистику задач;
- поиск;
- фильтр по статусу;
- список задач;
- пагинацию.

## 5. Работа с задачами

Показать основные действия:

1. Создать новую задачу.
2. Отредактировать задачу.
3. Изменить статус задачи.
4. Удалить задачу.
5. Показать, что задачи видны только владельцу.

## 6. Поиск, фильтрация и статистика

Показать:

- поиск по названию;
- поиск по описанию;
- фильтр `Новая`;
- фильтр `В работе`;
- фильтр `Выполнена`;
- обновление статистики по статусам.

## 7. Журнал действий

1. Выйти из `demo_user`.
2. Войти под `demo_admin`.
3. Открыть личный кабинет.
4. Перейти в `Журнал действий`.
5. Показать:

- дату действия;
- пользователя;
- тип действия;
- описание;
- фильтр по типу действия.

## 8. Django admin

Под `demo_admin` открыть:

```text
http://localhost:8000/admin/
```

Показать:

- пользователей;
- задачи;
- журнал действий.

## 9. Адаптивность

Сузить окно браузера и показать:

- перестроение шапки;
- адаптивные фильтры;
- карточки задач;
- пагинацию;
- формы создания и редактирования.

## 10. Проверка тестов

В терминале выполнить:

```bash
docker-compose exec web python manage.py check
docker-compose exec web python manage.py test accounts tasks activity
```

Ожидаемый результат:

```text
System check identified no issues
OK
```

## 11. Что обязательно проговорить

- Проект написан на Django без frontend-фреймворков.
- Данные хранятся в PostgreSQL.
- Запуск выполняется через Docker Compose.
- Используется стандартная Django auth.
- У каждого пользователя свои задачи.
- Администратор может смотреть журнал действий.
- История разработки ведется через GitHub Issues и ветку `develop`.
